## 功能简介

ASP Assistant 是一款用于《明日方舟》**卫戍协议**玩法的透明悬浮侧边辅助工具，运行时叠加在游戏窗口上，提供以下功能：

### 干员浏览与筛选
- 干员与装备默认使用**左侧外扩**筛选布局。可通过标题栏齿轮打开**设置**，切换到顶部布局，切换时保留筛选条件和偏好。设置底部可查看当前版本和检查更新。
- 可在**设置 → 侧窗不透明度**中调整整个侧窗的不透明度（20%～100%，默认 100%），拖动即时生效并自动保存。
- 侧栏可展开、收起、按组折叠及重置。已选标签显示在筛选侧栏中，收起时保留数量提示。
- 盟约标签显示 PRTS 原图小图标（筛选区 16px、摘要和卡片 13px），离线可用；缺图或损坏时仍显示名称
- 干员默认按**等阶从低到高**排列，筛选后保持此顺序
- **等阶**、**核心盟约（阵营）**、**附加盟约**、**特质类型**、**触发时机**支持多选；同类标签匹配任意一项，不同类别同时满足
- **叠层**与**本局状态**保持单选；点击“全部”清空该类筛选，取消最后一个标签后自动回到“全部”
- 支持实时**名称搜索**
- 按**本局状态**（正常 / 禁用）过滤显示
- 可在每张干员卡片上手动**标记 / 取消标记**为禁用

### 核心与附加盟约自动禁用检测
- 自动检测“确认本局信息”准备页，不需要先添加追踪目标；侧栏顶部显示检测状态
- 保持顶部核心盟约及两行附加盟约完整可见，自动读取名称与图标状态：绿色可用，灰色且带阵容标记视为禁用，无需滚动到干员头像列表
- 有核心盟约的干员：**所有核心盟约都不可用**时自动禁用。双核心盟约中只禁用一个时，干员仍可用
- 无核心盟约的干员：**没有任何可用的附加盟约**时自动禁用
- 两部分识别完成后更新整份自动禁用名单；只改变附加盟约也会更新，识别不完整时保留已有名单并重试
- 识别完成后，筛选区与干员卡片中本局不可用的核心／附加盟约会淡化显示，悬停提示“本局禁用”；标签仍可筛选，清空记录或进入新局时重置标注
- 策略选择、自选编队页面保留结果；下方禁用头像列表不再作为识别入口
- 点击“截屏录入”可强制重扫当前盟约，识别不依赖干员皮肤头像模板
- 支持连续多次截屏排队执行，界面显示"X 录入任务执行中"进度提示
- 手动禁用/取消禁用会保留至清空或下一局；清空后，相同盟约状态不会立即重新填入，点击“截屏录入”可恢复自动结果

### 敌人
- 在 BP 的「确认本局信息」页自动记录敌方领袖、特训敌人和战场编号，供本局随时查看。敌方领袖和战场均可在页签内手动选择，未识别时也可选择并查看路线；手动选择保留至下一局，可随时切回自动识别。领袖选项参照[PRTS 领袖资料](https://prts.wiki/w/卫戍协议·规程/PRTS盟约记录#领袖)，缩略图参照[战场一览](https://prts.wiki/w/卫戍协议·规程/战场一览)。
- 假想敌：铳、假想敌：鳍、矩兽的路线取自随附参考图。第 14、15 回合各自选择左侧或右侧，站位待确认时可查看两侧。第 15 回合仅在触发隐秘核心时适用。

### 装备追踪
- 浏览全部装备数据，按**等阶**、**类型**多选筛选
- 点击追踪按钮，将装备或干员加入本局追踪列表

### 干员与装备详情
- 点击干员或装备卡片上的**详情**，查看头像、盟约、普通与精锐效果、装备配方及有出处的实战小知识。
- 干员的**本体技能**页列出实际拥有的技能，显示最高可训练等级的效果、技力消耗、初始技力及回复方式。
- **社区投票**的汇总对访客开放。作业站账号登录后，可为每名干员投一项常用技能、推荐最多五件适用装备，各提交一次。公开结果仅显示汇总票数，装备仅显示前五。

### 游戏状态感知（OCR）
- 实时扫描识别商店物品、场上 / 备战区干员
- 自动统计当前盟约层数
- 在游戏画面上以**悬浮标记**高亮已追踪的目标
- 商店追踪直接识别名称栏，干员和装备共用逻辑；支持同名多卡及分辨率缩放，不依赖皮肤颜色、立绘或卡框模板。职业图标干扰文字时会裁掉图标复读，并用完整名称库校验。
- 新皮肤保留商店布局时可直接使用；若名称栏位置或卡牌布局改变，需要调整识别区域和相对定位规则。

### 阵容搭配与分享
- 在**阵容**页签可新建、导入和管理多套阵容；顶部的**打开作业站**可在浏览器中打开卫戍阵容库。
- 桌面和网页版阵容编辑器支持选择 **1–30 名不重复干员**，并可为阵容多选核心和附加盟约标签。填写阵容名称与**作者名称**后保存。
- 阵容卡片会按所列干员、精锐状态和装备显示已激活盟约。计算包含调和加成，以及同一名干员同时携带变形同构体与对应装备时获得的盟约。
- 左侧可切换**干员 / 装备**页签，以每行 **3–4 个头像**展示目录。干员支持完整多选筛选（等阶、核心/附加盟约、特质类型、叠层、触发时机、本局状态），装备支持名称、等阶与类型筛选。
- 头像按批次在后台加载并跨窗口共享缓存，宫格仅创建可见行及少量预备行；加入/移除干员保留其余头像控件，搜索输入短暂合并后更新，减少开窗和面板操作时的卡顿。
- 将干员拖到右侧阵容区域加入，或双击/点击加入按钮；点击阵容头像后，在右下方统一编辑该干员。核心标记会显示在头像角落。
- 装备拖到干员头像上会填入空槽。拖到头像下的小装备槽或右下编辑区的指定槽位，可替换现有装备。点击小图标右上角 **×** 可清除。
- 每名干员可分别标记为**叠层核心**、**输出核心**，允许多人担任、同一人兼任。普通干员有两个装备槽，「暴躁铁皮」有四个。
- 搭配完成后点**下一步**编辑阵容介绍。左侧编辑 Markdown 说明，右侧流程图可切换画布和源码。可把上方头像和装备拖入画布，用中键平移，或右键节点创建连线、删除节点。拖动位置只在当前编辑窗口内生效，保存后的预览使用自动布局。
- 阵容页可切换**全部阵容 / 我的阵容 / 导入阵容**。卡片右侧提供**预览、追踪、分享、上传**；右键卡片可编辑或删除。追踪可一次加入可从商店获取的干员和已配置装备。
- 点击**分享**，作业站会生成并复制当前阵容的短链接。快照加密保存，有效期 90 天。需要公开发布时，在**设置 → 卫戍阵容库**登录，再点击卡片的**上传**。
- 复制短链接后，在桌面端点击**从剪切板导入**，或在作业站阵容编辑器中粘贴短链接。桌面端也兼容旧版分享文本。导入保留作者，并在**导入阵容**分类中创建新阵容。

### 其他
- 内置 47 句鲍勃简体中文语音，默认开启。可在「设置 → 默认鲍勃语音」试听或关闭。PC 内存采集可判断商店冻结、付费／免费刷新、干员招募、出售与精锐变化。PC 和 MuMu 的战斗帧可补充开战提示。首次全胜与后续全胜使用各自的台词，完整语音清单见[原版语音核对表](docs/bob-voice-coverage.md)。
- 可在同一设置卡片调整**随机语音频率**（0～1，默认 1）；战备时每隔随机 5～10 秒判定一次，按设置概率播放。0 为关闭随机闲聊，1 为每次判定都播放，修改自动保存。开局、战前和战斗结算等事件语音保持原来的触发方式。
- 启动和普通「检查更新」只检查正式版。「检查 Beta 版」必须每次在设置中手动点击；预览后仍需确认才会下载。
- 在设置中点击「发送反馈」，将近期应用日志和更新失败日志发送到卫戍阵容库，成功后显示反馈编号
- 窗口置顶、可自由拖动和缩放

## 运行要求

| 条件 | 说明 |
|------|------|
| 操作系统 | Windows 10 / 11（x64） |
| 运行库 | 安装包自带 .NET 8 Desktop Runtime 和 x64 VC++ CRT |
| 游戏客户端 | 明日方舟 PC 版（B 服 / 官服均可），或运行游戏的 Windows 安卓模拟器 |
| 游戏分辨率 | 推荐 16:9（1280×720 及以上） |

### 安装、覆盖安装与卸载

从[正式版发布页](https://github.com/Moonfair/ASP_Assistant/releases/latest)下载 Windows x64 安装包（`*-setup.exe`），退出正在运行的助手后按向导安装。已使用 v3.8.11 或 v3.9.0 Beta 的用户也可在 **设置 → 检查更新** 中升级；v3.8.10 及更早的 ZIP 版请直接运行安装包。

**Beta 只在软件内提供。** 从 v3.8.11 起，进入 **设置 → 检查 Beta 版**，阅读测试说明并确认安装。此选择仅对当次有效，不会订阅测试版。安装向导默认安装到 `%LOCALAPPDATA%\Programs\ASPAssistant`；从便携 ZIP 迁移后请从开始菜单打开 **ASP Assistant**，无需迁移个人阵容和设置。

在 Windows **设置 → 应用** 中找到 **ASP Assistant** 并选择 **卸载**。卸载会移除程序、快捷方式和属于本次安装的阵容链接关联，个人阵容与设置保留在 `%APPDATA%\ASPAssistant`，重装后可继续使用。

### 游戏来源

未设置过游戏来源时，助手默认自动检测 Windows 客户端，以及已开启 ADB 且正在运行《明日方舟》的 MuMu 和雷电实例。多个游戏窗口同时运行时，助手优先跟随前台的游戏窗口。已有的手动选择会保留，可在 **设置 → 游戏来源 → 选择游戏来源** 中切换到 **自动检测**。

手动连接模拟器时，可以固定一个实例。

1. 打开模拟器并进入明日方舟，在辅助工具的 **设置 → 游戏来源** 中选择 **选择游戏来源**。
2. MuMu 和雷电可直接从列表选择正在运行的实例。多开时根据实例名和编号选择，窗口重启后会重新查找已保存的实例。
3. 蓝叠、夜神、逍遥等可选择 **手动绑定 ADB**。选择模拟器窗口和其 ADB 程序，填写 `adb devices` 中对应的本机序列号。模拟器的 ADB 端口变更后，在这里更新序列号。

模拟器窗口在前台时，商店标记贴在游戏画面上。模拟器截图优先使用增强模式，可回退到普通 ADB 或窗口截图。ADB 未开启时，手动选择 MuMu 或雷电实例仍可通过窗口截图尝试识别。推荐使用横屏 16:9。

使用官方 Windows 客户端（已验证版本 2.7.91）时，助手自行读取卫戍协议对局内存。**数据** 页显示战斗时间、干员伤害和占比。

**MuMu 12 战斗统计：** 在 MuMu 中开启 ADB 和 Root，启动适配的《明日方舟》Android ARM64 2.7.91，在助手中自动检测或选择对应的 **MuMu 实例**（不是「手动绑定 ADB」）。进入战斗后直接查看原来的**数据**页，无需安装或运行 ArkDPS。采集使用游戏内时间，物理、法术、真实、元素伤害与 PC 端口径相同，不把治疗算作伤害。没有 Root 或版本不匹配时不读取伤害；不会自动开启 Root。同一实例内请只运行一个游戏客户端。

模拟器的回合、商店等级和金币仍来自画面识别，房间和队友内存信息仍仅支持 Windows 客户端。其他模拟器的截图识别不变。

## 构建方法

```bash
# 克隆仓库
git clone <repo-url>
cd ASP_Assistant

# 拉取游戏数据（首次运行或版本更新后）
cd data
python fetch_spdatabase.py
python fetch_operator_skills.py

# 构建并运行
cd ..
dotnet run --project src/ASPAssistant.App
```

> **提示**：`fetch_spdatabase.py` 需要 Python 3.10+ 以及 `requests` 和 `Pillow` 库。
> ```bash
> pip install requests Pillow
> ```

## 打包发布

使用 PowerShell 7，在项目根目录执行（将版本号换成本次发布版本）：

```powershell
dotnet test ASPAssistant.sln -c Release
python -B -m unittest discover -s tests
./scripts/publish.ps1 -Version 1.2.3
```

打包机需安装 .NET 8 SDK、Visual Studio / Build Tools 的 C++ 工具和 Inno Setup 6.7.3（`winget install --id JRSoftware.InnoSetup -e --version 6.7.3`）。脚本在独立临时目录发布自包含应用，把 x64 CRT 放到 Maa DLL 旁，验证运行库和数据资源，再生成 `publish/ASPAssistant-v1.2.3-win-x64-setup.exe`。可用 `-OutputDirectory` 指定安装包输出目录，`-VcRedistDirectory` 指定 CRT 来源，`-IsccPath` 指定编译器。

推送 `vX.Y.Z` 标签时，GitHub Actions 调用同一脚本，验证安装、覆盖安装和卸载后，将同一个 EXE 发布到 GitHub Release 和 OSS，并更新下载页。测试标签 `vX.Y.Z-beta.N` 只部署到软件内的独立更新通道，不创建 GitHub Release，也不改动正式版清单。

发布包只包含 Windows x64 原生库、当前目录数据、浏览图片和 OCR 模型，不包含旧皮肤匹配模板、调试符号、Python 缓存或个人设置。皮肤下载脚本仍保留供开发参考。

### 用户数据与更新缓存

- 追踪设置：`%APPDATA%\ASPAssistant\tracking.json`。保存采用临时文件替换；损坏文件会保留为 `tracking.corrupt-*.json`，并恢复为空列表。
- 游戏来源：`%APPDATA%\ASPAssistant\game-target.json`。
- 阵容数据：`%APPDATA%\ASPAssistant\lineups.json`。采用临时文件替换保存；读取失败时显示提示并阻止覆盖，便于先备份、修复原文件。
- 应用日志和更新失败日志：`%APPDATA%\ASPAssistant\logs`。
- 更新临时目录：`%TEMP%\ASPAssistant-Update\<独立任务 ID>`。下载失败或安装结束后清理本次任务，不删除其他正在进行的更新。

## 数据文件说明

```
data/
├── operators.json          # 干员数据（含阵营、特质等）
├── equipment.json          # 装备数据
├── operator_skills.json    # 明日方舟本体技能
├── catalog_tips.json       # 卫戍实战小知识及来源
├── skin_avatar_map.json    # 皮肤头像 → 干员名映射（Ban 位识别用）
├── source_metadata.json    # 赛季、抓取时间、上游修改时间及 SHA-256
├── icons/
│   ├── operators/          # 干员头像（来自 PRTS Wiki）
│   └── skin_avatars/       # 皮肤头像（Ban 位识别模板）
├── fetch_spdatabase.py     # 卫戍数据拉取 / 皮肤下载脚本
└── fetch_operator_skills.py # 同步目录干员的本体技能
```

### 常用脚本命令

| 命令 | 功能 |
|------|------|
| `python fetch_spdatabase.py` | 拉取最新干员 / 装备数据 |
| `python fetch_operator_skills.py` | 拉取当前目录干员的本体技能 |
| `python fetch_spdatabase.py --download-skins` | 下载皮肤头像并重建映射文件 |
| `python fetch_spdatabase.py --apply-mask` | 为现有皮肤头像补白色背景 |
| `python fetch_spdatabase.py --skip-icons` | 跳过头像下载，仅更新 JSON |

当前默认拉取 **卫戍协议：规程**（`act3autochess / V3_1`）。旧赛季存档可用
`--season 2`（盟约上半）或 `--season 3`（盟约下半的存档版本）拉取；这些命令会替换当前本地数据。
上游文件的最后修改时间和本次抓取时间记录在 `data/source_metadata.json`，均带有时区信息。
